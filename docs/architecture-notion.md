# 051 BOX 앱 구성 정리

> 화면(프론트엔드) · 서버(백엔드) · 데이터베이스를 **각각 다른 무료 서비스**에 올려 나눠 맡긴 구조. 현재 운영 비용 0원.

## 한눈에 보기

| 구분 | 사이트 | 주 언어 | 주요 도구 |
|---|---|---|---|
| 프론트엔드 (화면) | Vercel | TypeScript | Next.js 16 (React), Tailwind CSS, Canvas 2D |
| 백엔드 (서버) | Render | JavaScript (Node.js) | Express 5, zod, web-push |
| 데이터베이스 | Supabase | SQL (PostgreSQL) | RLS 보안 규칙, DB 함수, pg_cron, Realtime, Storage, Auth |
| WOD 원본 | Google Sheets | - | 코치가 쓰는 시트를 서버가 읽어 옴 |
| 코드 저장 · 배포 | GitHub (kwkworks/051-box) | - | push 하면 Vercel · Render 자동 배포 |

- 웹사이트: https://051-box.vercel.app
- 서버 주소: https://zero51-box.onrender.com

## 전체 흐름

```
 휴대폰/PC (설치형 웹앱)
    │  ① 화면 받기 ─────────▶ Vercel (Next.js 화면)
    │  ② 기록·WOD·관리 요청 ─▶ Render (Express 서버) ──▶ Supabase DB
    │  ③ 로그인·실시간 채팅·캐릭터 위치 ─────────────────▶ Supabase (직접 연결)
    │
    ◀── 푸시 알림 ── Render ◀── 매일 20:25·30·35 Supabase(pg_cron)가 호출
                      └─ WOD는 구글 시트에서 읽어 옴
```

---

## 1. 프론트엔드 — Vercel

**언어 · 도구:** TypeScript, Next.js 16(React), Tailwind CSS, 박스 공간은 Canvas 2D로 직접 그림

**하는 일:** 사용자가 보는 모든 화면 (박스 공간, 채팅, WOD, 1RM 기록 · 순위, 게시판, 관리자 화면)

**장점**
- GitHub에 올리면 자동 배포
- Next.js를 만든 회사라 궁합이 가장 좋음
- 전 세계 CDN으로 빠르고 HTTPS 자동

**단점**
- 무료(Hobby) 플랜은 원칙적으로 비상업용 → 유료 서비스로 키우면 유료 플랜 검토 필요

**선택 이유**
- 한 코드로 아이폰 · 안드로이드 · PC를 모두 지원하는 설치형 웹앱(PWA)을 만들기에 가장 쉬운 조합

---

## 2. 백엔드 — Render

**언어 · 도구:** JavaScript (Node.js), Express 5, zod(입력 검사), web-push(알림)

**하는 일:** 입력값 검사, 요청 횟수 제한(도배 방지), 구글 시트에서 WOD 읽기, 푸시 알림 발송, 관리자 기능

**장점**
- 무료 + GitHub 자동 배포
- 일반 서버라 시간 제한 없이 푸시 발송 같은 작업 가능
- 푸시용 비밀키를 서버에만 보관 가능

**단점**
- 무료 플랜은 15분간 요청이 없으면 잠듦 → 첫 접속 시 30초~1분 대기
  - 대응: "깨우는 중" 화면 추가, WOD 알림은 20:25에 먼저 깨움
- 배포 중 1~2분 잠깐 끊김

**선택 이유**
- DB 관리자 비밀키(service_role)를 **아예 쓰지 않기로** 결정
- 서버는 사용자 본인 권한으로만 DB에 접근하고 검사 · 처리만 담당
- 비밀키 유출로 모든 데이터가 뚫리는 위험을 원천 차단

---

## 3. 데이터베이스 — Supabase

**언어 · 도구:** PostgreSQL(SQL) — RLS 보안 규칙, DB 함수, pg_cron 예약 작업

**함께 쓰는 기능:** 로그인(카카오 · 구글), 실시간 채팅 · 캐릭터 위치(Realtime), 사진 저장(Storage)

**장점**
- DB · 로그인 · 실시간 · 파일 저장이 한 곳에
- RLS로 "본인 기록만 수정", "승인된 회원만 보기" 같은 규칙을 DB가 직접 지킴 → 서버에 버그가 있어도 데이터 보호
- 보안 규칙 77개 시나리오 테스트 통과

**단점**
- 무료 플랜은 1주일간 사용이 없으면 일시정지
- 용량 제한: DB 500MB, 파일 1GB → 사진이 쌓이면 확인 필요
- SQL을 직접 써야 해서 실수 위험 → 괄호 검사기(check_sql.py)로 보완

**선택 이유**
- 로그인 · 실시간 채팅 · 사진을 따로 만들 필요가 없음
- 보안 규칙을 DB 수준에서 걸 수 있어 소규모 커뮤니티에 가장 적합

---

## 4. 보조 구성요소

| 구성 | 쓰는 이유 | 주의할 점 |
|---|---|---|
| 구글 시트 (WOD 원본) | 코치가 이미 쓰던 시트를 그대로 읽어 따로 입력할 필요 없음 | 시트 형식(열 위치, 줄바꿈)이 바뀌면 화면이 깨질 수 있음 |
| 웹 푸시 (VAPID) | 앱스토어 없이 알림 발송 | 아이폰은 홈 화면에 설치한 앱에서만 수신 |
| GitHub | 코드 보관 + 자동 배포 | 공개 저장소라 비밀값은 절대 올리지 않음 (.env 제외) |

---

## 5. 앱스토어 앱 대신 웹앱(PWA)을 고른 이유

**장점**
- 앱스토어 심사 · 등록비(애플 연 약 13만 원) 없음
- 수정하면 몇 분 안에 모든 회원에게 반영
- 코드 하나로 모든 기기 지원

**단점**
- 아이폰은 설치가 수동 (공유 → 홈 화면에 추가)
- 아이폰은 화면 방향 고정 불가, 알림은 설치한 앱에서만

**보완한 것:** 설치 안내 화면, QR 포스터, 카카오톡 → 사파리 열기 버튼, 안드로이드 원탭 설치 버튼
