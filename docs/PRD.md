> 상태: **v0.4 (확정, 개발 기준 문서)**
> 작성자: 크로스핏051 운영자/코치
> 최종 수정: 2026-11-03

## 1. 문제 정의

현재 박스 운영 커뮤니케이션은 **네이버 카페**로 하고 있다.

| 현재 방식 | 문제점 |
|---|---|
| 내일 WOD, 오늘 기록, 공지를 네이버 카페에 게시 | 박스 운영에 맞춰진 도구가 아니라 WOD, 기록, 공지가 일반 게시글에 섞여 묻힌다 |
| 대회, 이벤트 정보를 운영자가 직접 찾아서 하나씩 게시 | 운영자에게 반복 작업 부담이 생긴다 |
| 대회에 나가고 싶은 회원들이 **오프라인에서 따로 모여** 신청 | 누가 참가하는지 파악하기 어렵고 신청 과정이 번거롭다 |
| 회식 같은 회원 모임 | 참석 인원 파악이 어렵다 |
| WOD의 "75%" 같은 강도 | 회원마다 매번 계산기로 자기 무게를 계산한다 |
| 오늘 기록은 화이트보드에만 남음 | 박스에 오지 않으면 기록을 볼 수 없고, 회원이 앱에 직접 입력하게 하면 참여율이 떨어진다 |

**한 줄 정의:** 실제 크로스핏051 박스를 옮겨놓은 **2D 가상 공간**에서 내 캐릭터로 돌아다니며 WOD, 공지, 대회, 모임, 1RM 게시판을 확인하고, 박스 밖에서도 회원들끼리 연결되는 **박스 전용 커뮤니티 웹앱**.

**성공 기준 (운영 1개월 후)**
- 활성 회원의 70% 이상이 앱으로 WOD를 확인한다.
- 대회 참가 신청이 오프라인 모임 없이 앱에서 100% 처리된다.
- 회원의 50% 이상이 캐릭터를 꾸미고 1RM을 1개 이상 등록한다.

## 2. 타겟 유저

| 역할 | 설명 | 주요 행동 |
|---|---|---|
| **관리자** (운영자/코치) | 박스 운영자, 코치 | WOD/공지/대회 등록, 기록 사진 업로드, 가입 승인, 휴무일 관리 |
| **회원** | 승인된 박스 회원 (20~40대, 운동 전후로 폰 확인) | WOD 확인, 출석 체크, 1RM 기록, 대회/모임 참가, 2D 공간에서 교류 |
| **승인 대기자** | 가입했지만 아직 승인되지 않은 사용자 | "승인 대기 중" 화면, 닉네임/캐릭터 설정만 가능 |

## 3. 핵심 기능 (MVP)

| # | 기능 | 작성 | 열람 | 설명 |
|---|---|---|---|---|
| F1 | **소셜 로그인** | | | 카카오, 구글 (네이버 제외) |
| F2 | **가입 승인** | 관리자 | 관리자 | 신규 가입자는 `pending`. 관리자가 승인해야 이용 가능 |
| F3 | **오늘/내일 WOD** | 관리자 | 회원 | 날짜별 WOD 1개. 본문 + 강도 항목(종목, %) |
| F4 | **WOD 무게 자동 계산** | 시스템 | 본인 | 내 1RM × WOD % → "내 무게 78.75kg" (정확한 값, 반올림은 회원이 직접) |
| F5 | **기록 사진 (리더보드)** | 관리자 | 회원 | 관리자가 화이트보드 사진을 WOD에 첨부. 회원은 사진으로 기록 확인 |
| F6 | **출석 체크 + 스트릭** | 회원(본인) | 회원 | 하루 1회 출석 버튼. **일요일과 휴무일(법정공휴일 + 관리자 지정)**을 제외한 모든 날이 연속이어야 스트릭 유지 |
| F7 | **공지사항 (상단 고정)** | 관리자 | 회원 | 고정 공지는 항상 맨 위에 표시 |
| F8 | **대회/이벤트 + 참가 신청** | 관리자 | 회원 | 일시, 장소, 신청 마감, 정원. 버튼으로 참가/취소, 명단 자동 정리 |
| F9 | **회원 모임 (회식 등)** | 회원 | 회원 | F8과 같은 구조. 회원 누구나 개설 가능 |
| F10 | **1RM 게시판** | 회원(본인) | 회원 | 종목을 골라 기록. 목록에 없는 종목은 직접 입력. 내 이력 + 종목별 박스 순위 |
| F11 | **PR 자동 축하** | 시스템 | 회원 | 1RM이 기존 최고 기록보다 높으면 "명예의 벽"에 자동 게시 |
| F12 | **2D 박스 공간** | | 회원 | 실제 박스를 옮긴 맵. 오브젝트에 다가가면 해당 게시판이 열림 |
| F13 | **실시간 함께 보기** | | 회원 | 접속 중인 회원 캐릭터가 실시간으로 보이고 말풍선으로 인사 (메시지는 저장하지 않음) |
| F14 | **캐릭터 꾸미기** | 본인 | 회원 | 피부색, 머리 모양/색, 상의/하의 색, 신발 색, 액세서리 조합 |
| F15 | **빠른 메뉴** | | 회원 | 공간을 돌아다니지 않고 메뉴에서 게시판을 바로 열기 (모바일 편의) |

### 이번 MVP에서 하지 않는 것
- 결제, 회원권 관리 / 여러 박스 동시 운영
- 네이버 로그인, 푸시 알림, 댓글, AI 기능 (다음 버전 후보)
- 채팅 기록 저장 (말풍선은 실시간 휘발성)

## 4. 화면 구성

### 4-1. 2D 박스 맵 (실제 크로스핏051 기반, 탑뷰 픽셀 스타일)

```
┌───────────────────────────────────────────────────────┐
│ [상장 벽]   [팀 배너 벽]          [RECORD 화이트보드]   │  ← 버건디/노랑 띠
│ 명예의벽(PR)  모임 게시판           WOD + 기록 사진      │
│                                                       │
│   ║  ║  ║  ║  ║   풀업 리그 + 링        [에어바이크 x4] │
│   ║  ║  ║  ║  ║                                       │
│        검은 고무 매트 (운동 공간)            ▮ 노란기둥 │
│                                                       │
│ [바벨/플레이트 랙]                         ▮ 노란기둥 │
│  1RM 게시판                                           │
│               [대회 포스터 벽]   (◉ CROSSFIT 051)      │
│                대회/이벤트       [데스크] 공지 + 출석   │
│                                        [입구] ← 시작   │
└───────────────────────────────────────────────────────┘
```

| 오브젝트 | 실제 박스 | 열리는 게시판 |
|---|---|---|
| RECORD 화이트보드 | Strength / Conditioning 화이트보드 | WOD + 내 무게 + 기록 사진 |
| 데스크 | 원형 로고 데스크 | 공지사항, 출석 체크 |
| 대회 포스터 벽 | "멋지다 051 역도왕" 포스터 | 대회/이벤트 |
| 팀 배너 벽 | 팀 이름 배너 | 회원 모임 |
| 바벨/플레이트 랙 | 플레이트, 바벨 거치대 | 1RM 게시판 |
| 상장 벽 | 상장, 메달 | 명예의 벽 (PR 축하 피드) |

**조작:** PC는 방향키/WASD로 이동하고 Space/E로 열기. 모바일은 화면을 탭하면 그 위치로 이동하고, 오브젝트 근처에서 "열기" 버튼 표시.

### 4-2. 페이지

| 경로 | 화면 | 접근 | 주요 요소 |
|---|---|---|---|
| `/login` | 로그인 | 누구나 | 카카오, 구글 로그인 버튼 |
| `/pending` | 승인 대기 | 승인 대기자 | 안내 문구, 닉네임/캐릭터 설정 링크 |
| `/` | **2D 박스 공간** | 회원 | 맵, 내 캐릭터, 다른 회원, 상단 HUD(🔥스트릭, 출석 버튼), 빠른 메뉴, 말풍선 입력 |
| `/avatar` | 캐릭터 꾸미기 | 로그인 사용자 | 파츠 선택 + 실시간 미리보기, 닉네임 |
| `/wod` | WOD | 회원 | 날짜 이동(어제/오늘/내일), 본문, 내 무게 계산표, 기록 사진 |
| `/notices` | 공지 | 회원 | 고정 공지 상단, 상세 펼치기 |
| `/events` | 대회·이벤트·모임 | 회원 | 탭(대회/이벤트/모임), 마감 임박 표시, 모임 만들기 |
| `/events/[id]` | 상세 | 회원 | 참가/취소, 참가자 명단, 정원 |
| `/one-rm` | 1RM | 회원 | 내 종목별 1RM 입력/이력, 종목별 박스 순위 |
| `/wall` | 명예의 벽 | 회원 | PR 축하 피드 |
| `/admin` | 관리자 | 관리자 | 가입 승인, 역할 관리, WOD/공지/대회 작성, 기록 사진 업로드, 휴무일 관리 |

- 게시판 페이지 상단에는 항상 "← 박스로 돌아가기" 버튼이 있고, 돌아가면 마지막 위치에서 다시 시작한다.
- 모바일 우선 반응형. 모든 화면에 로딩 상태와 에러 메시지 표시.

### 4-3. 주요 사용자 흐름
1. **가입:** 로그인 → `/pending` (캐릭터 꾸미기 가능) → 관리자 승인 → 2D 박스 입장
2. **매일:** 박스 입장 → 데스크에서 출석 체크 → 화이트보드에서 오늘 WOD와 내 무게 확인
3. **기록:** 관리자가 수업 후 화이트보드 사진 업로드 → 회원이 화이트보드에서 확인
4. **대회:** 관리자가 대회 등록 → 회원이 포스터 벽에서 "참가" → 관리자가 명단 확인
5. **PR:** 랙에서 1RM 입력 → 최고 기록 경신 시 명예의 벽에 자동 게시

## 5. 데이터 구조 (Supabase Postgres)

```
profiles           회원 정보 (auth.users와 1:1, 가입 시 트리거로 자동 생성)
├─ id              uuid PK (= auth.users.id)
├─ nickname        text (2~16자)
├─ role            'pending' | 'member' | 'admin'   (기본 pending)
├─ avatar          jsonb  {skin, hair, hairColor, top, topColor, bottom, bottomColor, shoes, acc}
└─ created_at

wods               날짜별 WOD
├─ id, wod_date (date UNIQUE), title, content
├─ lifts           jsonb  예) [{"movement":"back_squat","percents":[70,75,80]}]
└─ created_by, created_at, updated_at

wod_photos         기록 사진 (화이트보드)
├─ id, wod_id → wods (cascade), storage_path
└─ uploaded_by, created_at

holidays           휴무일 (일요일은 자동 제외라 저장하지 않음)
└─ day (date PK), name

attendance         출석
└─ user_id, attend_date   PK(user_id, attend_date)   (날짜는 서버의 한국 시간으로만 기록)

notices            공지
└─ id, title, body, pinned, created_by, created_at, updated_at

events             대회 / 이벤트 / 모임
├─ id, kind        'competition' | 'event' | 'gathering'
├─ title, description, starts_at, location, link_url
├─ signup_deadline, capacity (NULL = 제한 없음)
└─ created_by, created_at

event_participants 참가 신청
└─ event_id, user_id, created_at   PK(event_id, user_id)

one_rm_records     1RM 기록 이력
├─ id, user_id
├─ movement        text (목록 키 또는 직접 입력한 종목명)
├─ is_custom       bool
├─ weight_kg       numeric (0 < x ≤ 500)
└─ achieved_on, created_at

activities         명예의 벽 피드 (DB 트리거만 작성 가능)
└─ id, user_id, kind ('pr'), payload jsonb, created_at
```

**종목 목록:** 백스쿼트, 프론트스쿼트, 오버헤드스쿼트, 데드리프트, 클린, 파워클린, 클린앤저크, 스내치, 파워스내치, 푸시프레스, 스트릭트프레스, 벤치프레스, 쓰러스터 (+ 직접 입력)

**스토리지:** `wod-photos` 버킷 (비공개). 회원만 서명된 URL로 열람, 관리자만 업로드. 이미지 형식만, 5MB 이하.

**실시간:** Supabase Realtime 비공개 채널 `box-space`. Presence(누가 접속 중인지 + 캐릭터 정보), Broadcast(위치 이동, 말풍선). DB에 저장하지 않음.

## 6. 기술 설계와 보안

기술 선택(스택, API, 배포 구조)과 보안 설계는 이 문서에 넣지 않고 [design.md](design.md)에 따로 기록한다.
보안 요구사항 요약: 승인된 회원만 데이터를 볼 수 있고, 회원은 본인 기록만 수정할 수 있으며, 관리자 권한과 정원 제한 같은 규칙은 화면이 아니라 **DB 안에서** 강제한다.

## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 카카오 로그인에서 이메일을 받으려면 비즈 앱 전환이 필요할 수 있다 | 닉네임과 프로필 사진만 요청하고, 닉네임은 앱에서 다시 설정 |
| Vercel Hobby는 비상업적 용도 | 시범 운영 후 상업 운영으로 전환하면 Pro 검토 |
| Supabase 무료 프로젝트는 7일 동안 요청이 없으면 일시정지 | 매일 쓰는 서비스라 영향 적음. 멈춰도 복구 가능 |
| Realtime 무료 한도 (동시 접속 200명) | 박스 1곳 규모에서는 충분 |
| 저작권 | ZEP 등 외부 캐릭터/맵 에셋은 쓰지 않고 모든 그래픽을 코드로 직접 그림 |
| 2D 공간이 모바일에서 불편 | 빠른 메뉴로 모든 게시판에 바로 접근 가능 |
