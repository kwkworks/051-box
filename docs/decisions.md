# 결정 기록 (Decision Log)

진행하면서 내린 결정과 그 이유를 기록한다.

## D1. 서비스 주제: 크로스핏 박스 커뮤니티
- **배경:** 운영자로서 네이버 카페로 WOD, 공지, 대회 정보를 관리하는 데 불편을 느꼈다. 특히 대회 신청을 회원들이 오프라인에서 따로 모여서 하고 있다.
- **결정:** 박스 전용 커뮤니티 웹앱을 만든다.

## D2. 가입 방식: 가입 후 관리자 승인
- **검토한 대안:** 초대코드 / 초대코드 + 승인
- **이유:** 초대코드는 유출되면 외부인도 가입할 수 있다. 승인 방식이 가장 안전하고 구현도 단순하다.

## D3. 기술 스택: Next.js + Supabase + Vercel
| 대안 | 장점 | 단점 |
|---|---|---|
| **A. Next.js + Supabase + Vercel (선택)** | 저장소 1개, 배포 1곳. 콜드스타트 거의 없음. RLS로 보안 | JS/TS 필요 |
| B. FastAPI + Supabase + Render | Python, 백엔드 구조가 명확함 | 무료 플랜은 15분 미사용 시 서버가 잠들고 깨어나는 데 30초~1분. 배포 2곳 |
| C. Express + Supabase + Render | Node 백엔드 분리 | B와 같은 단점 |

- **이유:** 회원은 운동 전에 폰으로 WOD를 잠깐 확인하므로, 첫 접속 때 30초 이상 기다리게 되면 실제로 쓰기 어렵다.
- **주의:** Vercel Hobby(무료)는 비상업적 용도로 제한된다. 정식 상업 운영으로 전환하면 Pro 플랜을 검토해야 한다. Supabase 무료 프로젝트는 7일 동안 요청이 없으면 일시정지된다 (복구 가능).

## D4. AI 기능: 보류
- 검토: Gemini 무료 플랜(대회 공지 자동 정리), Claude API(계속 무료인 플랜 없음), Groq
- **결정:** AI보다 **무료 서비스 연동**을 우선한다. AI는 나중에 추가할 수 있는 후보로 남긴다.
- Gemini 무료 플랜을 쓰게 되면 입력 데이터가 구글 서비스 개선에 쓰일 수 있으므로 **개인정보는 보내지 않는다.**

## D5. 로그인: 카카오 + 구글 (소셜 로그인만 사용)
- 카카오, 구글은 Supabase 기본 제공.
- ~~네이버~~: Supabase 기본 제공이 아니라 커스텀 OAuth로 직접 연결해야 하고 공식 예시가 없다. 복잡도 대비 효과가 작아 **제외** (다음 버전 후보).
- 소셜 로그인을 붙여도 **관리자 승인 절차는 유지**한다 (카카오 계정만 있으면 아무나 들어오는 것을 막기 위해).
- 비밀번호를 직접 저장하지 않으므로 비밀번호 유출 위험이 없다.

## D6. 재방문 유도 기능: WOD 무게 자동 계산, 출석 스트릭, PR 자동 축하
- 기준: "회원이 매일 겪는 상황을 이 앱에서만 바로 해결해 주는가"
- **WOD 무게 자동 계산:** 이미 넣기로 한 1RM 기능과 연결되어 추가 작업이 적은데, 매일 써야 하는 이유가 생긴다.
- **출석 스트릭:** 휴무일(WOD가 없는 날)은 건너뛰고 계산해서, 쉬는 날 때문에 스트릭이 끊기지 않게 한다.
- **PR 자동 축하:** 커뮤니티 활성화. DB 트리거로만 생성해서 위조할 수 없게 한다.
- 제외: 응원/댓글, 푸시 알림 → 다음 버전 후보

## D7. 대회 / 이벤트 / 모임을 한 테이블로 관리
- 셋 다 "일시, 장소, 정원, 참가 신청" 구조가 같다. `kind` 컬럼으로 구분하고 참가 신청 로직을 하나로 공유한다.
- 권한 차이(모임은 회원도 작성 가능)는 RLS 정책에서 `kind`로 구분한다.

## D8. 출석 스트릭: 일요일 + 휴무일 제외
- 일요일과 법정공휴일, 관리자가 지정한 임시휴무일을 제외한 **모든 날**이 연속이어야 스트릭이 유지된다.
- 법정공휴일은 2026~2027년 목록을 미리 넣어두고, 관리자 화면에서 추가/삭제할 수 있다.
- 출석 날짜는 클라이언트가 보내지 않고 DB가 한국 시간 기준으로 기록한다 (날짜 위조 방지).

## D9. 리더보드: 회원 직접 입력 → 화이트보드 사진
- **이유:** 회원이 기록을 앱에 직접 입력하게 하면 참여율이 떨어진다. 박스는 이미 화이트보드에 기록을 적고 있다.
- **결정:** 관리자가 수업 후 화이트보드 사진을 WOD에 첨부하고, 회원은 사진으로 기록을 본다.
- 사진은 비공개 스토리지에 저장하고, 승인된 회원만 볼 수 있다.

## D10. 1RM: 종목 목록 + 직접 입력
- 회원이 종목을 골라 직접 기록한다. 목록에 없는 종목은 직접 입력할 수 있다.
- 목록에 있는 종목만 WOD 무게 자동 계산에 연결된다.

## D12. 배포 구성 수정: 프론트 / 백엔드 / DB 분리 (D3 대체)
- **배경:** 운영자가 "프론트엔드, 백엔드, DB가 각각 역할을 하도록 배포"할 것을 요구했다. 수업 자료 7개(03~07강)를 확인한 결과 이 방향이 수업의 기본 구조와 맞았다.
- **수업 근거:** 03강은 Next.js를 프론트로 선택, 04강은 "프론트는 백엔드에만 말하고 백엔드가 DB에 말한다" + Supabase, 05강은 프론트는 Vercel / 별도 API 서버는 Render, 07강은 DB 안에서 규칙 강제와 RLS.
- **결정:** 프론트 Next.js(Vercel) + 백엔드 Express(Render) + DB Supabase.
- **폐기:** 이전에 추천했던 Next.js 단일 배포(D3), Hono + Cloudflare Workers (수업에서 다루지 않음).
- **단점과 보완:** Render 무료 서버가 15분 미사용 시 잠든다 → 안내 화면과 외부 핑으로 보완 ([design.md](design.md) 2절).
- **예외:** 2D 공간의 실시간 위치 공유만 브라우저가 Supabase Realtime에 직접 연결한다 (비공개 채널 + RLS, 데이터 저장 없음).

## D13. 기술 내용을 PRD에서 분리
- 07강: "PRD에는 기술 선택을 넣지 않고, 설계 문서에 선택 이유를 기록한다."
- PRD는 문제/유저/기능/화면/데이터, 기술은 [design.md](design.md)에 기록한다.

## D14. 화면 스타일: 탑뷰 픽셀 (ZEP 방식)
- 비교: 사이드뷰 픽셀(데이브 더 다이버), 탑뷰 픽셀(ZEP), 쿼터뷰 복셀 3D(언레일드 2).
- **결정:** 탑뷰 픽셀. 넓은 박스를 자유롭게 돌아다닐 수 있고, 모바일 조작이 쉽고, 구현 난이도가 낮다.
- 꾸미는 재미는 캐릭터 편집 화면에서 크게 보여주는 방식으로 살린다.
- 3D(Three.js)는 수업 범위를 벗어나고 일정 부담이 커서 제외.

## D11. 2D 박스 공간 (ZEP 스타일)
- **배경:** 게시판만 있는 앱은 네이버 카페와 차별점이 약하다. 실제 박스를 옮긴 공간에서 돌아다니는 경험 자체가 재방문 이유가 된다.
- **맵:** 실제 크로스핏051 사진을 바탕으로 구성 (흰 벽, 검은 매트, 노란 기둥, 버건디/노랑 띠, 리그, 에어바이크, 화이트보드, 원형 로고 데스크, 상장 벽, 팀 배너 벽).
- **함께 보기:** 접속한 회원들이 실시간으로 보인다 (Supabase Realtime 무료, 비공개 채널로 회원만 접속).
- **캐릭터:** 파츠 조합형 (피부, 머리 모양/색, 옷 색, 신발, 액세서리).
- **빠른 메뉴:** 공간을 돌아다니지 않고 게시판을 바로 열 수도 있다 (모바일 편의).
- **구현:** 외부 게임 엔진 없이 Canvas 2D로 직접 구현하고, 그래픽은 모두 코드로 그린다 (저작권 문제 없음, 번들 크기 작음).

## D15. WOD 무게 표시: 정확한 값만 (2.5kg 반올림 폐기)
- **문제:** 2.5kg 단위로 가장 가까운 값에 반올림하자 1RM 105kg 기준 70% 72.5 / 75% 80 / 80% 85처럼 간격이 들쭉날쭉하고, 정해진 %보다 무겁게 나오는 경우가 생겼다.
- **검토:** 2.5kg 내림, 정확한 값 + 내림 값, 1kg 반올림, 정확한 값만
- **결정:** 정확한 값만 표시한다 (73.5 / 78.75 / 84kg). 플레이트 구성에 맞춘 반올림은 회원이 직접 한다.

## D16. 카카오 로그인: 비즈 앱 전환 + 이메일 선택 동의
- **문제:** Supabase는 카카오 로그인 요청에 `account_email`을 항상 포함하고, 카카오는 비즈 앱에서만 이메일 동의항목을 허용해서 KOE205 에러가 났다.
- **결정:** 개인 개발자 본인인증으로 비즈 앱 전환(무료) 후 이메일을 "선택 동의"로 설정한다. Supabase의 "Allow users without an email"을 켜서 이메일을 거부해도 가입할 수 있게 한다.
- **개인정보:** 이메일은 Supabase Auth 내부에만 저장되고, 앱 화면과 API에서는 사용하거나 노출하지 않는다.

# 1차 수정 (2026-11-04)

## D17. PR 글과 1RM 기록 연결 (삭제 연동)
- **문제:** 1RM 기록을 지워도 명예의 벽 PR 글이 남았다.
- **결정:** `activities.one_rm_id`를 `one_rm_records`에 외래키(on delete cascade)로 연결. 기존 글은 가장 가까운 기록과 연결하고, 원본이 이미 없는 글은 정리했다.

## D18. 채팅 기록: DB 저장, 7일 보관 *(D25로 대체)*
- **결정:** `chat_messages` 테이블. 승인된 회원만 보고 쓴다(RLS). 7일 지난 메시지는 새 메시지가 올 때 자동 삭제. 10초에 5개 제한(DB 트리거).
- **실시간:** 저장된 메시지만 Supabase Realtime(postgres_changes)으로 전달 → 받는 쪽에도 RLS가 적용되고, 저장 안 된 가짜 메시지는 퍼지지 않는다.
- 본인과 관리자는 메시지를 지울 수 있다(부적절한 메시지 정리).

## D19. 조작: Enter 채팅, 클릭으로 열기, 이름표, 게시판 모음
- Enter = 채팅 입력/전송, Esc = 닫기. 게시판 열기는 Space/E/클릭.
- 모든 오브젝트에 이름표를 달고 이름을 통일했다 (RECORD 화이트보드 → 📋 오늘의 WOD, 바벨 랙 → 🏋️ 1RM 기록, 명예의 벽 → 🎉 PR 명예의 벽).
- 입구 옆에 🗂 게시판 키오스크와 `/board` 페이지를 두어 모든 기능을 이름과 설명으로 모았다.
- 클릭 판정은 "가장 가까운 오브젝트"가 아니라 "클릭한 오브젝트에 손이 닿는지"로 한다 (키오스크 위 데스크가 대신 열리던 버그 수정). 이름표를 눌러도 반응한다.

## D20. 스피커 음악: 각자 유튜브 재생목록 *(D24로 대체)*
- **검토:** 관리자 음원 업로드, 무료 음원, 유튜브 재생목록
- **결정:** 회원마다 자기 유튜브 재생목록 주소를 넣고 스피커 근처에서만 재생. 주소는 각자 브라우저(localStorage)에만 저장.
- **광고:** 앱이 광고를 막는 건 불가능(유튜브 약관). YouTube Premium으로 같은 브라우저에 로그인돼 있으면 임베드에서도 광고 없이 재생된다. 일부 브라우저(아이폰 사파리 등)는 로그인 정보가 전달되지 않을 수 있다.
- **보안:** 입력 주소를 그대로 쓰지 않고 재생목록/영상 ID만 추출해서 임베드 주소를 새로 만든다. CSP `frame-src`는 www.youtube.com만 허용. 유튜브 정책에 따라 플레이어를 숨기지 않는다(300×200).

## D21. 캐릭터 v2: 24×32 픽셀, 16개 항목
- 픽셀 격자를 16×22 → 24×32로 키워 같은 화면 크기에서 더 섬세하게. 외곽선은 이미지 처리로 자동 생성.
- 항목 9 → 16개 (눈, 눈썹, 입, 수염, 상의 무늬, 모자, 안경, 운동 장비 추가). 이전 캐릭터 데이터(`acc`)는 새 항목으로 자동 변환.
- 그린 모습은 캐시해서 여러 명이 접속해도 성능 유지.

## D22. 스마트폰 앱: PWA 먼저
- **검토:** 스토어 앱(구글 1회 $25, 애플 연 $99, 심사, iOS는 Mac 필요, 애플은 웹을 감싸기만 한 앱을 거절하는 경우가 많음) vs PWA(무료)
- **결정:** PWA. manifest와 051 로고 아이콘(일반/마스커블/애플)으로 안드로이드·아이폰 홈 화면 설치 지원. 스토어 등록은 다음 단계 후보.

## D23. 구글 시트 WOD: 웹 게시 CSV + 가져오기 버튼
- **검토:** 웹 게시(공개 링크) vs Google API 서비스 계정(비공개, 설정·비밀키 관리 필요)
- **결정:** 웹 게시 CSV. 관리자가 주소 저장 후 버튼으로 가져온다. 무료 서버(Render)에는 예약 작업이 없어 자동 주기 실행 대신 버튼 방식.
- **보안(SSRF 방지):** `docs.google.com/spreadsheets/d/e/.../pub` 형식만 허용하고 주소를 다시 조립, 리다이렉트 목적지도 구글 도메인인지 확인, 10초·1MB 제한. 날짜는 지난 7일 ~ 앞으로 60일만.

# 2차 수정 (2026-11-04)

## D24. 음악: 유튜브 → 게임풍 BGM (D20 대체)
- **문제:** 유튜브 주소를 넣는 과정이 번거롭고 음량 조절이 어려웠다.
- **결정:** Web Audio로 칩튠 BGM을 브라우저에서 직접 합성 (사각파 멜로디, 삼각파 베이스, 아르페지오, 드럼, 128BPM 루프). 음원 파일이 없어 **저작권 문제 없음**, 다운로드 용량 0.
- 브라우저 정책상 첫 클릭/키 입력 후 재생. 상단 🔊 버튼에서 음량 슬라이더와 음소거. 설정은 각자 기기(localStorage)에만 저장.
- 유튜브 임베드를 없애면서 CSP `frame-src 'none'`으로 되돌렸다.

## D25. 채팅: 오늘 대화 + 내가 접속해 있던 동안만 (D18 대체) *(D40으로 대체)*
- **결정:** `chat_sessions` 표에 "내가 박스에 있던 시간대"를 기록. 클라이언트는 직접 쓰지 못하고 DB 함수(`chat_session_start`, `chat_session_ping`)로만 시작/갱신해 시간 위조를 막는다.
- 30초마다 갱신하고, 90초 넘게 끊기면 갱신이 거부되어 새 접속으로 시작 → **없던 동안의 대화는 이어 붙어 보이지 않는다.**
- 조회 권한(RLS): 오늘 0시(KST) 이후 메시지 중 내가 쓴 것 + 내 접속 시간대 안에 쓰인 것. 화면에서는 이전 접속 대화를 노란 구분선("이전 접속 HH:mm ~ HH:mm 대화")과 흐린 글씨로, 지금 접속은 초록 구분선으로 나눈다.
- 어제 이전 메시지와 접속 기록은 자동 정리.

## D26. 관리자 채팅 제한 / 전체 잠금
- 회원별 제한: 1시간 / 오늘 자정까지 / 해제. `profiles.chat_muted_until`에 저장하고, 회원은 스스로 풀 수 없다(트리거).
- 전체 잠금: 관리자 화면 스위치. 잠겨도 관리자는 쓸 수 있다(공지용). 잠금·제한은 API가 아니라 **DB 트리거에서 강제**하므로 API를 우회해도 막힌다.

## D27. PR 명예의 벽: 첫 기록 포함, 오늘 기록만
- **문제:** 어제 100kg, 오늘 200kg을 넣어도 벽에 안 올라온 경우가 있었다. 원래 규칙은 "이전 기록보다 높을 때"라서 그 종목의 **첫 기록**은 올라가지 않았다.
- **결정:** 첫 기록도 "내 최고 기록"으로 보고 게시("첫 기록!" 표시). 벽은 오늘(KST) 기록만 보여주고 매일 0시에 새로 시작한다. 이전 기록은 1RM 게시판에 그대로 남는다.

## D28. 2D 공간 정리 + 액션
- **문제:** 활성화할 것들이 모두 모여 있어 조잡해 보였다.
- **결정:** 벽 게시판·화이트보드·랙 등은 장식(충돌만 있음)으로 바꾸고 이름표 제거. 열 수 있는 것은 🗂 게시판 키오스크 하나. 조작법은 우측 상단 "⌨️ 조작법" 버튼 안으로 숨김.
- 액션: 점프(Space), 앉기(C), 춤(Q), 달리기(Shift/모바일은 켜기·끄기). 키는 물리 키 코드로 판단해 한글 입력 상태에서도 동작. 자세와 점프는 Realtime으로 다른 회원에게 전달하고, 받은 값은 허용 목록으로 검증한다.

## D29. WOD 입력 양식 시트
- 기존 시트는 칸 구조가 달라 연결이 어려웠다. 관리자 계정에 새 양식 "051 BOX WOD 입력 양식"을 만들었다 (기존 파일은 수정하지 않음).
- 날짜 칸은 날짜 검증으로 달력 선택, 요일은 수식으로 자동 표시(일 빨강, 토 파랑, 오늘 노랑), 칸: 날짜·요일·제목·스트렝스·본 와드·비고(Time Cap)·강도. "달력" 탭에서 연·월을 넣으면 그 달 WOD가 달력으로 보인다.
- 가져올 때 스트렝스/본 와드/비고를 `[Strength]`, `[Conditioning]` 블록으로 합치고, 제목이 비면 "M월 D일 (요일) WOD"로 채운다.

## D30. 모바일 화면: 채팅창 이동·접기, 넓은 시야
- 휴대폰에서 채팅창과 액션 버튼이 화면을 가렸다. 채팅창은 손잡이(⠿)로 끌어서 옮기고(두 번 누르면 제자리), ✕로 접으면 최근 메시지와 안 읽은 수만 보이는 작은 버튼이 된다. 휴대폰은 처음에 접힌 상태. 위치·접힘은 기기에 저장.
- 휴대폰 기본 배율을 낮춰 박스를 더 넓게 보여주고, ＋/－ 버튼으로 0.6~1.6배 조절.

## D31. 맵 정리 + 유산소 머신 + 들고 다니는 운동기구
- 의미가 사라진 스피커(음악이 BGM으로 바뀜)는 없앴다. 플라이오 박스는 아래쪽 기구 줄로, 정수기는 오른쪽 벽으로 옮기고 물통을 그려 알아보기 쉽게 했다.
- 오른쪽 유산소 구역: 에어바이크·바이크에르그 각 4대, 로잉머신 4대, 벽쪽 스키에르그 4대.
- 이름표 대신 구조물을 누르면 이름이 잠깐 뜬다 (화면은 깔끔하게, 궁금하면 확인).
- 운동기구: 바벨 랙, 케틀벨 랙, 덤벨 랙, 메디신볼 더미에서 E(또는 누르기)로 집고, 들고 다니다 E로 내려놓는다(제자리로 돌아감). 들고 있을 때 Space는 머리 위로 들어올리기.
- 기구는 각자 손에 "복사본"을 드는 방식이라 여러 명이 동시에 집어도 충돌이 없다. 들고 있는 기구는 실시간으로 다른 회원에게도 보이고, 받은 값은 허용 목록으로 검증한다.

## D32. 오른쪽 벽 머신 줄 + 머신 타기, 철봉, 플로팅 조이스틱
- 유산소 머신을 오른쪽 벽에 한 줄로 정리 (위에서부터 로잉 5, 스키에르그 2, 바이크에르그 2, 어썰트바이크 2, 트레드밀 2). 옆에서 E/버튼/누르기로 타면 자리에 고정되고 종류별 동작(로잉: 시트 왕복, 스키: 팔 올렸다 끌어내리기, 바이크: 페달, 트레드밀: 제자리 달리기). 움직이거나 E로 내린다.
- 철봉(풀업 리그 두 줄): 아래에서 매달리기 → ←→로 손을 옮겨 이동, Space 풀업, ↑↓/E로 내려오기.
- 모바일 이동: 요즘 모바일 게임·메타버스 앱에서 가장 많이 쓰는 **플로팅 조이스틱** 채택 (사용자 확인). 화면 아무 곳이나 누른 채 밀면 그 자리에 조이스틱이 생기고, 끝까지 밀면 달리기. 짧게 탭하면 기존처럼 그 위치로 이동/열기.
- 타기·매달리기 상태는 실시간으로 공유하고, 받은 값은 머신 번호·철봉 줄 허용 범위로 검증한다.

## D33. 모바일 소리·채팅 사용성
- 휴대폰 브라우저는 손가락을 뗄 때만 소리 재생을 허락해서 첫 화면에서 음악이 안 나왔다 → 여러 입력에서 재생을 시도하고, 아이폰용 무음 잠금 해제를 넣었다.
- 화면을 내리거나 다른 앱으로 가면 음악이 멈추고, 돌아오면 이어서 재생.
- 휴대폰에서 채팅창을 펼치면 액션·메뉴 버튼을 숨겨 입력창을 가리지 않게 했다 (접으면 다시 보임).
- (추가) 머신 사이를 한 칸씩 띄워 캐릭터가 설 자리를 만들고, 머신 앞(플라이휠·콘솔)이 넓은 필드 쪽을 보게 뒤집었다. 13대에 간격까지 넣으면 25줄이 필요해서 박스 맵을 아래로 4줄 늘리고 데스크·키오스크·입구·기구 랙을 함께 옮겼다. 정수기는 위쪽 벽(화이트보드 옆)으로.

## D34. 앱 목적에 맞춰 정리: 머신·기구는 장식으로 (D31·D32 일부 보류)
- 앱의 주 목적은 모임 모집, WOD 기록 확인, 내 무게 기록·계산, 공지·이벤트 확인이다. 머신 타기·철봉·기구 들기는 성능 부담은 작지만 휴대폰에서 안내 버튼이 자주 떠서 화면이 복잡해지고 목적과 거리가 있어 **보류**했다 (사용자 확인).
- 남긴 것: BGM, 점프·앉기·춤·달리기, 플로팅 조이스틱, 구조물을 누르면 이름 보기.
- 머신은 8대(로잉 3, 스키에르그 2, 바이크에르그 1, 어썰트바이크 1, 트레드밀 1)를 오른쪽 벽에 한 칸씩 띄워 장식으로 두고 필드 쪽을 보게 했다. 기구 랙(바벨·케틀벨·덤벨·메디신볼)도 장식.
- 맵 크기를 40×26칸에서 34×22칸으로 줄였다 (약 25% 작게). 모든 빈 칸이 입구에서 걸어갈 수 있는지 스크립트로 확인.
- 휴대폰 액션 버튼은 반투명으로 (누르면 선명하게).

## D35. WOD 공개 시각: 다음 날 WOD는 전날 오후 8시 30분부터
- 지난 WOD와 오늘 WOD는 언제든, 다음 날 WOD는 전날 20:30(KST)부터 회원에게 공개. 그보다 먼 미래 WOD는 관리자만 미리 본다.
- **강제는 DB(RLS)에서:** `wod_visible(date)` 함수로 wods 조회 정책을 바꿔, API를 거치지 않고 직접 조회해도 공개 전 WOD는 0행. 기록 사진도 WOD를 볼 수 있을 때만.
- 화면: 공개 전 날짜는 🔒 "오늘 오후 8시 30분에 공개돼요" 안내. 관리자는 미리 보면서 "회원에게는 ~에 공개" 표시.

## D36. 초대하기: 공유만 (승인 절차 유지)
- 검토: 자동 승인 초대 링크 vs 공유 버튼 → **공유만** (사용자 선택). 게시판과 메뉴의 "📨 초대하기"가 휴대폰 공유 창(카카오톡 등)을 열고, 지원하지 않으면 초대 문구+주소를 복사한다. 가입한 사람은 지금처럼 관리자 승인 후 이용.

## D37. 테스트 사용자 배포 전 보안 보강 (독립 보안 점검 결과 반영)
- 점검 결과 치명·높음 등급 문제는 없었고, 중간 3건·낮음 몇 건을 고쳤다.
- **요청 제한:** IP 기준 제한이 박스 와이파이를 함께 쓰는 회원들을 한꺼번에 막을 수 있어, 로그인 후에는 회원 계정 기준으로 바꾸고 접속 유지 신호는 쓰기 제한에서 뺐다. IP 기준은 무차별 요청만 막도록 넉넉하게.
- **닉네임 사칭:** DB에서 허용 문자만(보이지 않는 문자 금지), 대소문자 무시 중복 금지. 카카오 이름이 같으면 가입 시 뒤에 번호를 붙인다. 채팅 이름은 실시간 정보가 아니라 DB 회원 정보에서 가져오고, 관리자 메시지에는 "관리자" 표시.
- **가입 스팸:** 익명 로그인은 회원 정보를 만들지 않음. Supabase 대시보드에서 이메일 가입·익명 로그인 끄기 확인 필요.
- **도배:** 하루 상한(1RM 20개, 모임 5개, 채팅 접속 50번)을 DB 트리거로 강제.
- **기타:** 기록 사진 저장소도 공개된 WOD 사진만 열람, 구글 시트 가져오기는 리다이렉트마다 구글 주소인지 확인.
- 보류: 실시간 이동 정보 위조(다른 사람 캐릭터를 내 화면에서만 움직이게 보이는 수준), CSP의 inline script 허용. 영향이 작아 테스트 이후 검토.

## D38. 관리자: 회원 기록 관리
- 회원 목록의 "📋 기록 관리"에서 그 회원의 1RM 기록(지우면 PR 축하 글도 함께 삭제)과 모임 글을 확인·삭제. DB에 관리자 삭제 권한 추가.
- 관리자 화면 맨 위 "🔑 관리자가 할 수 있는 일"에서 승인/승인 취소, 관리자 지정, 기록 삭제, 채팅 제한·잠금, 게시판 관리 위치를 안내.

## D39. 아이폰 설치 쉽게: QR 포스터 + 화살표 안내
- 애플은 웹사이트가 설치 창을 자동으로 띄우는 것을 허용하지 않고, 앱스토어 등록은 비용·심사(웹 감싸기 앱 거절 사례)가 커서 보류.
- **QR 포스터(/poster, 관리자):** 아이폰 기본 카메라로 찍으면 카카오톡을 거치지 않고 사파리로 바로 열린다. QR은 브라우저에서 이미지로 생성(qrcode 라이브러리), 인쇄용 레이아웃.
- **화살표 안내:** 아이폰 사파리로 들어오면 화면 아래에서 공유 버튼 위치를 화살표로 가리키며 3단계 안내 (iOS 18 이하: 아래 가운데 공유 / iOS 26: 오른쪽 아래 ⋯ / iPad: 오른쪽 위). 카카오톡에서 열면 "사파리로 열기" 버튼. 닫으면 3일간 숨김, 앱으로 열면 표시 안 함.
- 아이폰은 사파리와 홈 화면 앱의 로그인 정보가 따로라서, "설치 → 앱에서 로그인" 순서를 안내한다 (로그인 화면에서도 안내가 뜬다).

## D40. 채팅: 오늘 대화 전체 + 읽은 위치 기억 (D25 대체)
- **문제:** "내가 박스에 있던 동안만" 규칙 때문에 휴대폰으로 게시판을 보거나 화면을 꺼 둔 사이의 PC 대화가 안 보여서, 서로 대화가 끊긴 것처럼 느껴졌다.
- **결정:** 승인된 회원은 오늘(한국 시간 0시부터) 대화를 모두 본다 (RLS). 어제 이전 대화는 지금처럼 자동 삭제.
- **읽은 위치:** `profiles.chat_read_at`에 마지막으로 읽은 시각을 저장 (휴대폰·PC 공통). 바꾸는 건 `chat_mark_read()` 함수로만 (본인 것만, 앞으로만). 다시 들어오면 "여기까지 읽었어요 · 새 메시지" 구분선과 함께 그 위치를 보여주고, 접은 채팅 버튼에는 안 읽은 수를 표시.
- 채팅 목록을 맨 아래까지 보면 읽음 처리, 내가 보내면 구분선 없이 최신 대화로 이동.
- 실시간 연결이 끊겼다 돌아올 때 · 화면이 다시 보일 때 · 30초마다 서버에서 다시 받아 맞춘다 (휴대폰 화면 꺼짐 대비).

## D41. 무게 단위 파운드(lb) + 네임드 WOD 시간 기록
- 크로스핏051은 파운드로 측정한다. 1RM은 lb로 입력·저장하고, 화면에는 kg 환산값을 함께 보여준다 (예: 225 lb (102.1 kg)). WOD % 무게 계산도 lb + kg.
- 기존 기록은 kg으로 입력된 것이라(사용자 확인) 0007에서 ×2.20462로 변환했다. 명예의 벽 기존 PR 글도 함께 변환.
- 네임드 WOD(Fran, Grace, Helen, Murph 등 15개 + 직접 입력)는 **시간**으로 기록한다. 기록마다 `unit`('lb' | 'time')이 있고, DB 제약으로 단위와 값이 맞는지, 목록 종목인지 강제한다.
- 시간 기록은 **짧을수록 좋다**: 첫 기록이나 더 빠른 기록만 PR, 순위는 빠른 순. PR 글에는 "0:20 단축"처럼 표시.

## D42. 승인 취소 회원의 기록: 숨기기 + 관리자 전체 삭제
- 검토: 숨기기 / 승인 취소 시 자동 삭제 / 숨기기 + 삭제 버튼 → **숨기기 + 완전 삭제 버튼** (사용자 선택)
- 승인을 취소하면(승인 대기로 돌아가면) 그 회원의 1RM·네임드 WOD 기록과 순위, 명예의 벽 PR 글, 채팅, 만든 모임, 참가 명단이 다른 회원에게 보이지 않는다. **DB(RLS)가 강제**하고, 다시 승인하면 그대로 돌아온다. 정원 계산에서도 빠진다.
- 관리자는 계속 볼 수 있고, "기록 관리 → 기록 전체 삭제"로 완전히 지운다 (닉네임을 직접 입력해야 진행, 관리자 계정은 대상 아님).

## D43. 가입 거절 + 다시 신청
- 승인 대기 목록에서 "거절"을 누르면 `rejected` 상태가 되어 목록에서 빠진다 (다른 신청자 승인에 방해되지 않게). 거절된 신청은 관리자 화면 아래 "거절한 신청"에 접혀 있고, 거기서 승인할 수도 있다.
- 거절된 사람은 로그인하면 "가입이 거절됐어요" 화면에서 닉네임을 고치고 **다시 가입 신청**할 수 있다. 다시 신청은 DB 함수(`reapply_membership`)로만, 거절 → 승인 대기로만 바뀐다 (스스로 회원이 될 수는 없음).
- 거절된 사람의 기록도 승인 취소 회원처럼 다른 회원에게 보이지 않는다.

## D44. 박스 순위 남/여 구분 + 내 기록 찾기
- `profiles.gender`('M' | 'F' | 없음)를 추가. 본인이 프로필(캐릭터 꾸미기 화면)에서 고른다. 성별을 안 고른 회원은 "전체" 순위에만 나온다.
- 박스 순위는 **남자 / 여자 / 전체** 탭, 처음에는 내 성별 탭. 서버가 종목마다 세 가지 상위 10명을 함께 보낸다.
- 내 최고 기록: **검색**(종목 이름), **종류 필터**(리프트 / 네임드 WOD / 직접 입력), **정렬**(최근 기록순 / 이름순 / 기록 많은 순). 종목을 누르면 그 종목 기록 변화가 펼쳐지고(최고 기록 표시), 거기서 삭제. 따로 있던 "내 기록 이력"은 여기로 합쳤다.

## D45. 푸시 알림 (공지 · 대회·이벤트 · 회원 모임 · 내일 WOD 공개)
- 표준 웹 푸시(VAPID) + 서비스 워커(`/sw.js`, 알림만 처리하고 페이지는 캐시하지 않음). 안드로이드 크롬은 바로, 아이폰은 홈 화면에 설치한 앱(iOS 16.4+)에서만.
- 회원은 게시판 화면 "🔔 알림 설정"에서 이 기기 알림을 켜고, 종류별로 켜고 끈다 (`profiles.notify_prefs`, 모든 기기 공통). 테스트 알림 버튼.
- **service_role 없이 보내기:** 서버만 아는 `PUSH_SECRET`으로 DB 함수(`push_claim`)를 불러 받을 사람 목록을 받는다. DB에는 비밀값의 SHA-256 해시만 `private` 스키마에 저장(앱에서 접근 불가). 비밀값이 틀리면 아무것도 못 받는다.
- **중복 방지:** 같은 종류+대상(글 id, WOD 날짜)은 `private.push_log`로 한 번만 보낸다. 만든 사람은 받지 않는다. 만료된 구독(404/410)은 자동 정리.
- **오후 8:30 WOD:** Supabase pg_cron이 20:25(서버 깨우기)·20:30(발송)·20:35(예비)에 서버를 부른다. 서버는 20:30 이후, 내일 WOD가 있을 때만 보내고 하루 한 번만 실제 발송.
- 함께: 기록 사진 여러 장 한 번에 올리기, 관리자 사진 순서 바꾸기(◀ ▶, `wod_photos.sort_order`).

## D46. 앱 화면 세로 고정, 안드로이드 설치 버튼, 순위 시상대
- 화면 방향: manifest `orientation: portrait`(안드로이드 설치 앱은 세로 고정). 아이폰은 웹앱 방향 고정을 지원하지 않는다. 가로 안내 화면은 만들었다가 사용자 요청으로 뺐다(고정이 안 되면 안내 불필요).
- 안드로이드: 크롬이 설치 가능하다고 알려주면(beforeinstallprompt) 화면 아래에 "📲 앱 설치" 버튼 하나로 설치. 설치 이벤트는 앱 전체에서 한 곳(lib/installPrompt)에 보관해 게시판 설치 카드와 공유.
- 박스 순위 1·2·3위는 시상대(포디움) 위에 각자 캐릭터가 서고 기록(lb·kg 또는 시간)이 단에 표시된다. 4위부터는 목록. 서버가 1~3위의 캐릭터 모습을 함께 보낸다.

## D47. 무료 플랜 운영 대비: 매일 DB 백업, 사진 줄여 올리기, 용량 표시 (2026-11-05)

  - GitHub Actions가 매일 04:00(KST) `supabase db dump`로 역할·구조·데이터를 내보내고, AES256으로 암호화해 30일 보관 (`.github/workflows/db-backup.yml`, 복원은 docs/backup.md). 공개 저장소라 암호화는 필수.
  - 접속 주소는 IPv4가 되는 Session pooler. DB 비밀번호와 암호는 사용자가 GitHub 비밀값에 직접 입력 (Claude에게 전달하지 않음). service_role 키는 여전히 쓰지 않음.
  - 사진은 올리기 전 휴대폰에서 긴 변 1600px JPEG로 줄인다 (`lib/shrinkImage.ts`). 줄이지 못하면 원본 그대로.
  - 관리자 화면에 무료 한도 대비 사용량 막대 (`admin_usage()`, 관리자만 실행, 숫자만 반환). 80% 넘으면 경고.

## D48. 일정 수정 + 앱 아이콘 숫자 지우기 (2026-11-05)
- 대회·이벤트·모임을 만든 사람(또는 관리자)이 상세 화면에서 내용을 고칠 수 있다 (`PATCH /events/:id`). DB 권한(RLS)은 처음부터 작성자·관리자 수정을 허용하고 있어서 마이그레이션은 없다.
  - 종류(대회/이벤트/모임)는 바꿀 수 없다. 정원은 이미 신청한 인원보다 적게 줄일 수 없다.
- 앱 아이콘의 빨간 숫자는 휴대폰 알림창에 쌓인 푸시 알림 개수다. 앱을 열거나 다시 볼 때 알림창의 이 앱 알림과 숫자를 지운다 (`components/BadgeClear.tsx`).
- 지난 일정 보기 (2026-11-05): 일정은 자동 삭제되지 않고, 시작 12시간 뒤 목록에서만 빠진다. 대회·이벤트·모임 탭마다 "예정된 / 지난" 버튼으로 지난 일정을 최신순으로 본다 (기존 `GET /events?past=1`). 지난 일정은 참가 신청·취소를 막는다.
