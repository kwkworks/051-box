# 결정 기록 (Decision Log)

진행하면서 내린 결정과 그 이유를 기록한다.

## D1. 서비스 주제: 크로스핏 박스 커뮤니티
- **배경:** 운영자로서 네이버 카페로 WOD, 공지, 대회 정보를 관리하는 데 불편을 느꼈다. 특히 대회 신청을 회원들이 오프라인에서 따로 모여서 하고 있다.
- **결정:** 박스 전용 커뮤니티 웹앱을 만든다.

## D2. 가입 방식: 가입 후 관리자 승인
- **검토한 대안:** 초대코드 / 초대코드 + 승인
- **이유:** 초대코드는 유출되면 외부인도 가입할 수 있다. 승인 방식이 가장 안전하고 구현도 단순하다.

## D3. 기술 스택: Next.js + Supabase + Vercel
| 대안 | 장점 | 단점 |
|---|---|---|
| **A. Next.js + Supabase + Vercel (선택)** | 저장소 1개, 배포 1곳. 콜드스타트 거의 없음. RLS로 보안 | JS/TS 필요 |
| B. FastAPI + Supabase + Render | Python, 백엔드 구조가 명확함 | 무료 플랜은 15분 미사용 시 서버가 잠들고 깨어나는 데 30초~1분. 배포 2곳 |
| C. Express + Supabase + Render | Node 백엔드 분리 | B와 같은 단점 |

- **이유:** 회원은 운동 전에 폰으로 WOD를 잠깐 확인하므로, 첫 접속 때 30초 이상 기다리게 되면 실제로 쓰기 어렵다.
- **주의:** Vercel Hobby(무료)는 비상업적 용도로 제한된다. 정식 상업 운영으로 전환하면 Pro 플랜을 검토해야 한다. Supabase 무료 프로젝트는 7일 동안 요청이 없으면 일시정지된다 (복구 가능).

## D4. AI 기능: 보류
- 검토: Gemini 무료 플랜(대회 공지 자동 정리), Claude API(계속 무료인 플랜 없음), Groq
- **결정:** AI보다 **무료 서비스 연동**을 우선한다. AI는 나중에 추가할 수 있는 후보로 남긴다.
- Gemini 무료 플랜을 쓰게 되면 입력 데이터가 구글 서비스 개선에 쓰일 수 있으므로 **개인정보는 보내지 않는다.**

## D5. 로그인: 카카오 + 구글 (소셜 로그인만 사용)
- 카카오, 구글은 Supabase 기본 제공.
- ~~네이버~~: Supabase 기본 제공이 아니라 커스텀 OAuth로 직접 연결해야 하고 공식 예시가 없다. 복잡도 대비 효과가 작아 **제외** (다음 버전 후보).
- 소셜 로그인을 붙여도 **관리자 승인 절차는 유지**한다 (카카오 계정만 있으면 아무나 들어오는 것을 막기 위해).
- 비밀번호를 직접 저장하지 않으므로 비밀번호 유출 위험이 없다.

## D6. 재방문 유도 기능: WOD 무게 자동 계산, 출석 스트릭, PR 자동 축하
- 기준: "회원이 매일 겪는 상황을 이 앱에서만 바로 해결해 주는가"
- **WOD 무게 자동 계산:** 이미 넣기로 한 1RM 기능과 연결되어 추가 작업이 적은데, 매일 써야 하는 이유가 생긴다.
- **출석 스트릭:** 휴무일(WOD가 없는 날)은 건너뛰고 계산해서, 쉬는 날 때문에 스트릭이 끊기지 않게 한다.
- **PR 자동 축하:** 커뮤니티 활성화. DB 트리거로만 생성해서 위조할 수 없게 한다.
- 제외: 응원/댓글, 푸시 알림 → 다음 버전 후보

## D7. 대회 / 이벤트 / 모임을 한 테이블로 관리
- 셋 다 "일시, 장소, 정원, 참가 신청" 구조가 같다. `kind` 컬럼으로 구분하고 참가 신청 로직을 하나로 공유한다.
- 권한 차이(모임은 회원도 작성 가능)는 RLS 정책에서 `kind`로 구분한다.

## D8. 출석 스트릭: 일요일 + 휴무일 제외
- 일요일과 법정공휴일, 관리자가 지정한 임시휴무일을 제외한 **모든 날**이 연속이어야 스트릭이 유지된다.
- 법정공휴일은 2026~2027년 목록을 미리 넣어두고, 관리자 화면에서 추가/삭제할 수 있다.
- 출석 날짜는 클라이언트가 보내지 않고 DB가 한국 시간 기준으로 기록한다 (날짜 위조 방지).

## D9. 리더보드: 회원 직접 입력 → 화이트보드 사진
- **이유:** 회원이 기록을 앱에 직접 입력하게 하면 참여율이 떨어진다. 박스는 이미 화이트보드에 기록을 적고 있다.
- **결정:** 관리자가 수업 후 화이트보드 사진을 WOD에 첨부하고, 회원은 사진으로 기록을 본다.
- 사진은 비공개 스토리지에 저장하고, 승인된 회원만 볼 수 있다.

## D10. 1RM: 종목 목록 + 직접 입력
- 회원이 종목을 골라 직접 기록한다. 목록에 없는 종목은 직접 입력할 수 있다.
- 목록에 있는 종목만 WOD 무게 자동 계산에 연결된다.

## D12. 배포 구성 수정: 프론트 / 백엔드 / DB 분리 (D3 대체)
- **배경:** 운영자가 "프론트엔드, 백엔드, DB가 각각 역할을 하도록 배포"할 것을 요구했다. 수업 자료 7개(03~07강)를 확인한 결과 이 방향이 수업의 기본 구조와 맞았다.
- **수업 근거:** 03강은 Next.js를 프론트로 선택, 04강은 "프론트는 백엔드에만 말하고 백엔드가 DB에 말한다" + Supabase, 05강은 프론트는 Vercel / 별도 API 서버는 Render, 07강은 DB 안에서 규칙 강제와 RLS.
- **결정:** 프론트 Next.js(Vercel) + 백엔드 Express(Render) + DB Supabase.
- **폐기:** 이전에 추천했던 Next.js 단일 배포(D3), Hono + Cloudflare Workers (수업에서 다루지 않음).
- **단점과 보완:** Render 무료 서버가 15분 미사용 시 잠든다 → 안내 화면과 외부 핑으로 보완 ([design.md](design.md) 2절).
- **예외:** 2D 공간의 실시간 위치 공유만 브라우저가 Supabase Realtime에 직접 연결한다 (비공개 채널 + RLS, 데이터 저장 없음).

## D13. 기술 내용을 PRD에서 분리
- 07강: "PRD에는 기술 선택을 넣지 않고, 설계 문서에 선택 이유를 기록한다."
- PRD는 문제/유저/기능/화면/데이터, 기술은 [design.md](design.md)에 기록한다.

## D14. 화면 스타일: 탑뷰 픽셀 (ZEP 방식)
- 비교: 사이드뷰 픽셀(데이브 더 다이버), 탑뷰 픽셀(ZEP), 쿼터뷰 복셀 3D(언레일드 2).
- **결정:** 탑뷰 픽셀. 넓은 박스를 자유롭게 돌아다닐 수 있고, 모바일 조작이 쉽고, 구현 난이도가 낮다.
- 꾸미는 재미는 캐릭터 편집 화면에서 크게 보여주는 방식으로 살린다.
- 3D(Three.js)는 수업 범위를 벗어나고 일정 부담이 커서 제외.

## D11. 2D 박스 공간 (ZEP 스타일)
- **배경:** 게시판만 있는 앱은 네이버 카페와 차별점이 약하다. 실제 박스를 옮긴 공간에서 돌아다니는 경험 자체가 재방문 이유가 된다.
- **맵:** 실제 크로스핏051 사진을 바탕으로 구성 (흰 벽, 검은 매트, 노란 기둥, 버건디/노랑 띠, 리그, 에어바이크, 화이트보드, 원형 로고 데스크, 상장 벽, 팀 배너 벽).
- **함께 보기:** 접속한 회원들이 실시간으로 보인다 (Supabase Realtime 무료, 비공개 채널로 회원만 접속).
- **캐릭터:** 파츠 조합형 (피부, 머리 모양/색, 옷 색, 신발, 액세서리).
- **빠른 메뉴:** 공간을 돌아다니지 않고 게시판을 바로 열 수도 있다 (모바일 편의).
- **구현:** 외부 게임 엔진 없이 Canvas 2D로 직접 구현하고, 그래픽은 모두 코드로 그린다 (저작권 문제 없음, 번들 크기 작음).

## D15. WOD 무게 표시: 정확한 값만 (2.5kg 반올림 폐기)
- **문제:** 2.5kg 단위로 가장 가까운 값에 반올림하자 1RM 105kg 기준 70% 72.5 / 75% 80 / 80% 85처럼 간격이 들쭉날쭉하고, 정해진 %보다 무겁게 나오는 경우가 생겼다.
- **검토:** 2.5kg 내림, 정확한 값 + 내림 값, 1kg 반올림, 정확한 값만
- **결정:** 정확한 값만 표시한다 (73.5 / 78.75 / 84kg). 플레이트 구성에 맞춘 반올림은 회원이 직접 한다.

## D16. 카카오 로그인: 비즈 앱 전환 + 이메일 선택 동의
- **문제:** Supabase는 카카오 로그인 요청에 `account_email`을 항상 포함하고, 카카오는 비즈 앱에서만 이메일 동의항목을 허용해서 KOE205 에러가 났다.
- **결정:** 개인 개발자 본인인증으로 비즈 앱 전환(무료) 후 이메일을 "선택 동의"로 설정한다. Supabase의 "Allow users without an email"을 켜서 이메일을 거부해도 가입할 수 있게 한다.
- **개인정보:** 이메일은 Supabase Auth 내부에만 저장되고, 앱 화면과 API에서는 사용하거나 노출하지 않는다.
