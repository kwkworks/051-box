# 보안 테스트 기록 (RLS 검증)

수업 07강 방식: 실제 사용자 권한으로 "막혀야 하는 요청"을 보내서 DB가 실제로 막는지 확인한다.

## 방법

- 스크립트: [supabase/tests/rls_test.sql](../supabase/tests/rls_test.sql) (Supabase SQL Editor에서 실행)
- 각 시나리오를 실제 역할(`anon` / `authenticated` + 사용자 ID)로 바꿔서 실행한다. 관리자 권한으로 결과를 보는 것이 아니라, 앱 사용자와 똑같은 권한으로 요청한다.
- 테스트 계정: 관리자 D(카카오), 승인된 회원 A(구글), 승인 대기 C(테스트 중 임시 생성 후 삭제)
- 테스트로 만든 데이터(임시 계정, 모임, 기록, 메시지)는 실행 끝에 모두 삭제한다.

### 테스트 중 발견하고 고친 것
- 첫 실행에서 18번이 실패했다. 원인은 정책이 아니라 테스트였다. 실제 Realtime 서버는 접속을 검사할 때 채널 이름(`realtime.topic`)을 DB에 알려주는데, SQL Editor에서 직접 실행하면 그 값이 비어 있어 승인된 회원도 거부됐다. 테스트가 Realtime 서버와 똑같이 채널 이름을 설정하도록 고친 뒤 통과했다.
- 이 결과로 정책이 조건에 맞지 않으면 기본으로 거부한다(안전한 쪽으로 실패)는 점도 확인했다.
